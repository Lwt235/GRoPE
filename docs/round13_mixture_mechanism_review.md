# Round13 无标签机制诊断：不推进固定 OU 四分量

2026-10-30。本诊断不评估传感器真值，不计算 PCK，不改变 R12 失败、任何旧门槛或深度启动限制。[独立审计](../results/round13_mixture_mechanism_independent_audit/verification.json)已通过：全部 15 个积分矩阵（含 24×576 个 dense 像素分量）用独立 SciPy GL64 复算，概率最大误差 9.22e-15；240 行指标、120 行模式变化、输入/输出/源哈希、预测中心和全部小分量矩均核验通过。审计正确不等于科学门槛通过。

**建议停止把固定 OU4 当作下一轮正式候选，不扫描 ρ。** 它确实扩大了预测中心格的质量优势，但以明显降低原预测区域分布的逼近质量为代价；现有结果不支持“full4 的近似四峰是当前主要错误，收缩即可修复”的机制解释。这个结论限于固定的小规模前向诊断，不等于证明所有平滑方法对真值都无用。

在读取新前向结果前已冻结 [协议](../ROUND13_MECHANISM_PROTOCOL.md)、模型、runner、测试与三个旧训练 input archive。锁为 `3575f495c77bc483b2bc25ee5b8d5b510ce3ff91de01747d3dc978bac2aab1ce`。三个场景为 Harvard c3/c5/c6，各选 metadata-first pair [30,45] 和固定八个 q24 query `[0,6,13,20,26,33,40,47]`，共 24 个 query。全部 query 都与 432 个 g8 key 比较；21 个独立预测中心位于相机前方且在 FOV 内，仅这些中心进入中心格描述统计。没有丢弃任何分布评估行，也没有 zero/tiny-FOV 情况。

所有表示读取相同的 RGB 预测像素和父 token 内容，h=.5；dense 用每个 query 的全部 576 个预测像素 Gaussian。OU4 只对原 full4 做固定 `ρ²=2/3` 的矩保持变换。T=0/5 是事先固定的机制对照，不选择温度。17 个合成测试通过；实际输入上 full4/OU4/full1 对 dense 的均值最大误差为 2.13e-14，协方差最大误差为 7.44e-15。

OU4 在 **每个 query、两个温度下** 的 dense-reference KL 都比 full4 高，共 48/48 次；T=5 的宏平均 KL 为 full4 的 11.58 倍、L1 为 4.01 倍。三个场景均出现这一形状损失。它只多得到一个预测中心格 argmax，而同 h 的单 Gaussian 还更偏向中心。这说明此次收缩的主要作用是将形状向单 Gaussian 推近，不能解释为恢复了被四高斯近似丢失的真实区域细节。

加入内容本身就会改变 dense 参照的模式：dense 的 T0→T5 argmax 改变 7/24 次，预测中心格为 argmax 从 18/21 降为 13/21；full4 为 16/21→13/21。T5 下 full4 与 dense 仅一个 query 的 argmax 不同。因此在这批固定训练输入里，full4 大体忠实重现了“完整预测像素区域＋相同父内容”的模式。更强地向中心收缩是在改变该区域分布，不是单纯修补积分或压缩误差。

中心对齐数也不能当作更高定位正确率：中心来自预测深度的单独半像素中心射线，并没有与传感器真值比较；中心格包含关系与 PCK@8 亦不等价。dense 参照只代表现有预测几何，可能继承上游深度、可见性、内容偏差。仅三个训练 pair、每个八个查询，不能据此把机制外推到 R12 的全部验证失败。它足以否定当前继续扫描 OU 参数的理由，但不能给一个尚未验证的新方法背书。

后续应优先澄清同一输出应保留的中心条件信息，而不是继续加分量或试平滑参数。任何下一候选若仍声称同时处理区域与中心，应保持原来的区域 KL、分区、效率及同一分布 argmax 门槛；若改用另一个中心读出，应明确成为不同任务契约，不能追认原 gate 通过。真实 V 深度实验仍未启动；其准备文件和 geometry cache 保留，不以机制诊断代替实际效用。
