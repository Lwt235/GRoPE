# R70 RGB 高斯参数的只读解释检查

2026-11-04，R70尚在训练、旧评估尚未导出。该检查不添加拟合，不修改
已冻结用途比较或成功标准，不能用几何更好替代NVS画质收益，也不要求隐式
参数必须拟合真实深度才承认PE用途。仅复用旧val，保留确认集不读。

问题：RGB-only生成的中心/协方差是否对应传感器测到的区域几何？竞争解释：
参数只是优化图像损失的潜在表示，形状约束有作用但不能赋予物理解释。
不同PE的生成头共同训练，信息来源一致不意味着训练后的几何数值相同。
检查将改变后续对收益来源、是否需要更好几何来源的解释，不改变当前胜负判据。

固定对象：R70六个RGB角色各三种子的已选checkpoint；选模全部完成后读取，
不另选几何最好的checkpoint。参考条件为base，旧val全部32三元组、每个2张
参考图、每图192patch。统一使用coverage>0的区域（空区域无传感器参照），
并单独报告coverage>=.5的预设质量敏感性统计，不能择优称作主结论。

只运行原模型的RGB/相机stem及7参数生成头，不传传感器矩给生成器。分别记录
相机坐标下的预测μ/Σ和已有观察μ/Σ：深度绝对误差、绝对相对误差，完整
matrix-log形状的Frobenius距离，去迹后的matrix-log距离（去全局尺度），以及
预测/观察的trace与条件数分位数。初始固定生成头为公共参照，只计算一次。
传感器均值/矩来自本轮缓存，并非“真实最优3DGS参数”；因此这只是物理区域
矩的一致性检查，不证明参数可辨识或形状必要性。

CPU float32路径用于便宜的只读描述统计，正式NVS仍是原bf16路径；不将微小
数值差异作为结论。按三元组与两个参考视图等权，另保留patch计数及原始数组。
仅对不同PE的差异作描述，不进行温度/尺度/损失/模型选择扫描。图选择全部18组
固定顺序，不能挑最好看的种子。结果不能变成下一步必须通过的新门禁。

如果有图像收益且几何一致性改善，可支持进一步检验物理几何解释（仍非因果证明）；
如果图像有收益但几何无改善，应称作学到的高斯形式表示；如果给定深度组有收益、
RGB组没有，再结合此诊断考虑参数生成路径。任何分支都先完整报告R70原结果。
