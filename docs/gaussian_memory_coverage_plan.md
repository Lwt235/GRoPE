# 读取器训练场景覆盖：固定结构与样本预算

2026-11-10。用户授权设为目标并执行。本轮为历史数据开发诊断，不是新确认。

## 问题和比较

假设：原三个训练场景覆盖过窄，限制实际 VGGT view token 对参考信息的跨场景使用。保持模型、监督和训练预算，只把十二训练片段从三个场景各四片段改为十二场景各一片段。竞争解释包括参考 S=4 与查询 S=1 表示不匹配、恢复单视图 token 的目标不适合、参考几何质量和固定写入表示限制。本轮不把任何一个预先认定为病因。

四组为 Local/Center（277,202/273,604 参数）与 Wide/Direct（530,548/531,652 参数）；主配对是 Center−Local、Direct−Wide。复用窄覆盖的十二模型，新增宽覆盖四组各三个种子，共十二次训练。严格复制对应旧初始权重、AdamW 3e-4/wd .01、clip5、batch2、2000步最终模型、全patch等权MSE。固定 VGGT、原高斯写入器、PCA、中心距离项和 S=4/S=1 编码；不加模块、不扫描层/权重、不选评价最佳检查点。Center 的高斯写入器仍只在原三个场景上学过，因此本轮不能检验扩大写入器训练覆盖的效果。

## 数据选择与匹配

窄覆盖原十二片段按 fit_00…fit_11 排列。宽覆盖保留 fit_00/04/08（原三个场景的首片段），其余九个槽替换成九个不同场景的首片段。候选池仅含六个原开发场景和五个已下载 RGB 的 projection_confirmation_20261104 场景；均与十二主评价地点不同。按 SHA256(`GRoPE-memory-reader-coverage-20261110-v1:` + scene) 排序，取前九个，不查模型分数。保留完整候选排序和未选原因；不按本轮结果替换场景。

选中五个旧开发场景（harvard_c11、harvard_c8、mit_dorm_next_sj、hotel_umd、mit_76_studyroom）及四个旧投影场景（hotel_barcelona、harvard_computer_lab、hotel_graz、home_ac）。它们转为训练，不能继续计入未训练场景成绩。仅 mit_lab_hj 保留为辅助开发场景，不据一个场景建立一般结论。projection 的剩余 mit_1_242 不进入本轮评价。

每片段十三帧，参考 [0,4,8,12]，训练查询 [1,3,5,7,9,11] 各四种遮挡，留出查询 [2,6,10] 各两种遮挡。两覆盖组均十二片段、48参考图像、72训练查询、288遮挡样例，2000步各4000次样例呈现。新训练遮挡用被替换的旧 fit 槽作为 rectangle 哈希模板，逐槽/查询/样例固定相同的遮挡位置；采样索引序列与原模型配对。评价遮挡仍用各片段自己的旧规则。

主要评价严格沿用原十二场景的40–52与80–92片段，两覆盖组均未在这些地点优化。分别报告两批，主汇总先在同场景内平均两片段，再按十二场景等权；不能当作二十四独立场景。旧三个场景的留出视角/其他片段、新增训练场景留出视角和剩余一个开发场景分开报告。所有评价均为历史诊断；训练场景被重新指定是显式的数据开发，不是新确认。

本设计保持样本数而改变场景组成与每场景覆盖，能检验这一固定训练集合的扩大覆盖策略，不会唯一隔离抽象的场景数量、来源分布或数据难度。

## 评价与决定

主指标为全patch平均的归一化token MSE，另报遮挡/可见区和完整输入改变量。用配对场景×种子重采样报告区间，同时保留三个种子、十二场景和两片段方向。重点报告宽覆盖的记忆相对对照收益，以及该收益减去窄覆盖收益的差；单模型误差下降不能冒充记忆增量。移除/交换记忆只作机制辅助，不替代强对照用途。

- 两个配对都有明确、可重复的正收益，且相对窄覆盖改善：支持读取训练覆盖是一个限制，后续考虑联合读写。
- 仅 Direct 保留明确增量：下一步定位当前高斯写入/内容表示；不能直接认定压缩是唯一病因。
- 两者仍无净收益：结束此固定接法的扩量尝试，重新审视表示对齐和监督目标。不能据此否定所有场景记忆，也不排除不同规模训练。
- 小幅、混合或不确定：如实报告，不自动补种子/调参追求正结果。

实现核对限于数据与地点隔离、参考输入边界、冻结身份、初始权重与采样配对、有限损失/梯度、旧主评价分数回放、独立评分及实际图像审阅。复用已验证的 VGGT 接口，不因数据覆盖变化重做全套接口/数值审计。记录峰值显存、训练与缓存时间。启动前检查 GPU；空闲卡优先，否则沿用单个共享进程、12 GiB上限的约定，保护其他用户作业。
