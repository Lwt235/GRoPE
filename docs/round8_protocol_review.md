# 第八轮独立审查：对应与源值的诊断替换

2026-10-30。本轮只使用旧训练集和旧验证集，不能把结果作为新的独立测试。审查者不读取第七轮新测试标签或逐例预测。

## 实验能回答什么

五个独立重训角色为：预测对应/预测源值、GT 对应/预测源值、预测对应/GT 混合源值、GT 对应/GT 混合源值，以及同参数量的单视图 self-context 控制。保留第七轮的一次 attention、同一个预测头、1,000 步训练预算及五个配对种子。

这组实验检验额外知道对应或源深度能否帮助当前预测器。它不是可部署系统的性能，也不是严格上界。GT 对应包含真深度、投影和可见性判定，不能把提升全部归因于消除位置误差；GT 源值也改变 V 的分布。每个角色从头训练能减少冻结模型直接替换造成的分布变化，但不能消除上述解释边界。

主指标继续包含全部 query 传感器有效中心。只有在预定的原生传感器可见性/一致性检验通过时才替换路由；其余 query 保留预测 attention。必须同时报告这个固定 eligibility 子集和 fallback 子集的覆盖率及误差，但不能通过只保留前者改变主评价人群。GT 分支的存在是显式诊断信息，不应写作仍满足 RGB-only 输入合同。

## 两项干预需要保持的精确定义

GT 路由由 query 的传感器中心点投影至 key 图像，采用相邻 token 中心的四邻域 bilinear 权重，不复用第六轮区域高斯或面积标签。投影位于有效图像、但落在 token-center 凸包之外时，边界截断会产生额外近似；需要保存截断计数。没有有效对应时不填 GT 零值、不丢 query、不利用 target mask 关闭损失。

GT 源值仍是与第七轮一致的 patch 代表点：在 192×144 网格的每个 8×8 patch 内，将具有有效 native-nearest sensor depth 的位置替换为传感器值，缺测位置继续使用该位置的 RGB 预测。每个位置按自己的射线反投影，再求 3D 平均并变换到 query 坐标取 z；不能把平均 z 乘 patch 中心射线作为替代。这里的64个位置是缩放后网格位置，不是64个原生640×480像素。

混合源值采用和预测源值相同的有限值/范围约定，不额外输入有效率、GT mask 或可见性特征。Q/K 的预测几何在所有四个融合角色中保持不变，除路由替换外不接触 GT。单视图角色不能因数据包中含 oracle 字段而误读它们。GT route 的 QK 参数只从 fallback 行获取梯度，这是干预的后果；参数个数一致不代表每一层获得相同的梯度信息。

## 先检查传输是否存在有效信息

除学习后的结果，报告直接深度传输的四个组合，并在全部有效 query 和固定 eligible 子集分别计算。四邻域 GT 路由加 patch 平均源值即使接近真实，也未必复原 query 中心深度；表面边缘、patch 内多表面混合、nearest sensor sampling 和相机误差都会留下误差。

因此还应提供直接在投影位置读取源 sensor depth、反投影并转回 query z 的中心对应诊断，明确它与 patch V 的信息合同不同。该诊断帮助区分传感器/配准误差、patch 离散化和学习头的利用能力，不能作为模型成绩。如果联合 GT 干预没有改善而直接传输已经很准确，应先检查预测头是否实际使用 V；若直接传输也差，则不宜将结果简单归为 PE 无效。

## 如何据此决定是否继续

可以预先采用“相对容量匹配 singleview 的验证 AbsRel 至少降低2%，至少4/5种子与2/2验证场景同方向”作为继续投入的开发门槛。它不是领域标准，也不是独立确认阈值：这两处验证场景已反复用于 checkpoint 和研究选择。逐种子和逐场景结果比把相关像素当独立样本的显著性更有用。

准确路由配合原 V 的改善支持先检查预测位置与可见性；仅真实源值改善支持优先解决源信息质量；只有联合干预改善则说明两种误差可能共同限制当前模块。任何结论都要对照覆盖率、直接传输和同容量单视图，保留无改善的角色。所有修订需保留原始版本和结果，不在看到表现后换主指标、有效群体或干预定义。

## 实现审查状态

已只读审阅第八轮最终协议、输入导出、模型、训练器、直接传输与独立分析器。初审发现的导出协议文件名不一致、oracle 来源列表次序和 delta1 改善方向计数问题均在训练封存前修复。训练器按身份加入 oracle 数组，模型只在预定角色读取对应的特殊字段，主 query mask 未改变。没有剩余阻断项。

另完成三项独立实数据核验，全部结果保留为独立新文件：

- `experiments/round8_protocol_data_audit.py` / `results/round8_protocol_audit/verification.json`：全部704对旧开发数据通过原输入/标签哈希、eligibility子集、状态、四邻域质量守恒、像素重心、边缘clamp、64样本有效率及直接传输fallback检查。重心最大误差8.18×10⁻⁶像素；两个验证场景46,818个有效query中20,086个eligible，26,732个继续预测fallback。
- `experiments/round8_baseline_reproduction_audit.py` / `results/round8_baseline_reproduction_audit/summary.json`：pred_pred与第七轮full、singleview与第七轮singleview，共十个重训基线在全部选定参数、128×432预测、完整11次验证历史、最优step和逐pair指标上逐位一致，最大差异为0。训练数据与batch序列也相同。
- `experiments/round8_real_forward_audit.py` / `results/round8_real_forward_audit/summary.json`：固定每个旧验证场景首/末pair，对三个oracle角色×五种子共15个checkpoint进行CPU重放。最大预测差异1.44×10⁻⁶米；attention与独立稀疏路由/fallback合同误差为0。污染未使用GT字段不改变输出；zero-V/reverse-V改变输出；所有实际V/预测头梯度非零；GT路由在eligible-only损失下QK梯度严格为0，在fallback损失下非零。

独立分析的开发结果支持降低继续调整PE的优先级：gt_route相对singleview的AbsRel改善1.031%，虽五个种子和两个场景均值方向一致，但未通过预定2%门槛；gt_value和gt_both的收益明显更大。该现象支持“当前源值质量是重要限制”，不证明只有源值质量有问题。直接传输同时显示，GT中心路由搭配原预测patch值仍有较大误差，而传感器patch值明显更准确；patch平均与连续中心采样之间也仍有差距。需保持GT可见性选择与传感器辅助的诊断限定，不将这些成绩包装成部署改善或新测试确认。
