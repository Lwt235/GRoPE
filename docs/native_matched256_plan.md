# 原生基元数量对照：匹配的 256 训练与评价

2026-11-06，训练启动前确定。本次是旧数据开发诊断，不修改 relative5 公式，不替代已完成的官方确认结论。

## 问题与竞争解释

此前原生模型全部用 512 个基元训练。官方确认的 sparse256 中，relative5 对 Distance 的平均优势为 +2.005 pp，少量基元时的下降也较小，但这同时改变了训练—测试输入数量。

- 假设：区域支撑的方向和范围关系帮助有限基元表达；匹配 256 训练、选模、评价时，relative5 对 Distance 和固定球形仍有收益。
- 竞争解释：先前稀疏优势主要是适应数量变化，或来自某个训练/选模流程，而非有限观测本身。
- 本次只改变输入数量的训练/选模流程，不增加模块、扫描尺度或温度，也不重新访问官方 TEST 来选择方案。

## 固定比较

新增九次拟合：relative5、distance_mlp、fixed_isotropic5 × 种子 11/22/33。旧模型分别复用 R73、R65 和 native_shape_attribution 的同种子完整拟合及六条件预测，按哈希绑定。

沿用原 7,757 个官方 TRAIN 开发对象：6,227 fit、765 val、765 dev_eval。原始转换、2048-token 缓存、完整 13 维共同内容、骨干、参数初始化、优化器和增强均不变。训练 120 epochs / 46,800 updates，batch16；不是相同 FLOPs 或相同基元总曝光量的比较。

每步仍生成原 512 个采样索引和对应的旋转、jitter；仅在模型训练前截取前 256 个。因此对象顺序、完整随机数流和保留基元的增强与原 512 训练逐步配对。三个方法收到完全相同的 256 输入；不改变模型 state_dict 结构或采用关系投影重排。

每五轮及 epoch0 在原 val 对象的固定前 256 个基元上评估，仍取最小验证 CE 的最早检查点。所有九次拟合完成并固定检查点后才导出 dev_eval。原 512 模型按原 512-val CE 选择，不重新选模；因此跨训练数量比较是两个匹配数量流程的比较，不能完全排除验证输入数量改变的影响。

主要开发读数是 dev_eval 的 sparse256（固定前 256 个缓存基元），比较三方法。继续报告原六条件：base512、sparse256、dense1024、jitter02@512、tilt@512、permuted512。没有把本轮 base 改名为 256，避免与旧结果混淆。

## 分析与决定

完整报告 mCA、OA、CE、每种子/每来源/每类结果；置换只作实现检查。对 relative5−Distance、relative5−固定球形及固定球形−Distance，报告均值、三对种子差及条件于种子的类别区间、种子×类别区间（固定 10,000 次，随机种子 78001）。三个种子的区间只是旧开发数据敏感性描述。

主要比较为 256→256 的前两项；同时报告旧 512→256、512→512、新 256→512，以及 `(relative5−control)256→256 − (relative5−control)512→256` 配对差值，判断收益随训练数量如何变化。不依据结果追加种子、重新选模或切换主指标。

若两个强控制上的匹配稀疏收益均明确，保留“有限观测下的几何组织”作为值得继续验证的用途假设；若匹配后收益消失或反转而旧数量变化条件保留，收窄为数量变化适应的条件性用途；若分歧或区间宽，保持不确定，不把小负值或尾数差变成新门禁。这不证明高斯唯一、五个量最小、数据效率提升或 RGB/跨域一般有效。任何新设计都需要另外的未用数据确认。

## 执行与检查范围

仅新增适配器，原训练/模型/缓存文件不改动。启动前检查三个角色的共同初始化、训练输入截断、与原完整采样流一致、256 验证输入及一次真实旧 fit batch 的有限梯度更新。训练后核对预算、实际流摘要、选模规则及预测指标。沿用已有 CPU/GPU 回放检查；不增加静态积分或微小数值一致性的科学条件。

最多六张实际空闲 GPU 并行，每卡一项训练；连续占用检查、CUDA 探针和启动前复查。现有其他用户任务不停止；暂不启用共享卡。运行时限制 PyTorch 分配器为 16 GiB，预检必须证明足够。后台自动完成训练、统一选模、旧开发导出和汇总；正式科学解释由实际审阅补上。
