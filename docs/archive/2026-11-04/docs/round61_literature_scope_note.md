# R61运行期间的文献定位：高斯输入、基函数与相对关系

2026-11-02。在R61新评估预测尚未导出时查阅以下原始论文版本。本笔记不改变
冻结的R61对照、数据、优化预算或判定，也没有启动新的候选或读取确认集。
CVF页面返回403后使用arXiv原文；没有采用第三方自动论文解读作为证据。

[3D Gaussian Point Encoders，v1，§3.1–3.4](https://arxiv.org/html/2511.04797v1#S3)
把点对一组可学习高斯的响应线性混合成特征，并研究自然梯度和蒸馏的训练
方式。这是高斯空间基函数用于点表示的明确先例。它与本项目当前“从每个
观察区域的支撑矩构造token对关系”不同；论文的优化结论也不能直接作为
修改R61优化器的依据，R61的支撑矩不是待学习的高斯参数。

[CLIP-GS，v2，§4.1](https://arxiv.org/html/2412.19142v2#S4.SS1)
将真实3DGS的局部属性整理成token，再用Transformer形成表征。其完整系统
研究检索与分类。因此，“给Transformer输入3DGS参数”已有先例，不能把
这一宽泛表述当成本项目的新贡献。其系统结果也不能替代本项目对相对位置
关系的同骨干比较；外观、分组、预训练与位置关系需要区分。

对本项目的判断：核心对象需要明确为“由区域参数导出的相对位置编码”，
而非泛称“高斯编码”。目前的11维关系和单个两层MLP是一个可测试实现；
其一般性、完整协方差必要性和新颖性仍未建立。R61只回答法向/谱是否已经
足够，不能仅凭一轮归因结果宣称覆盖了这两个完整外部系统。

后续实际3DGS任务必须让强对照获得相同的颜色、透明度、尺度、旋转等公开
属性，并保持token形成方式一致，才能把额外收益归于PE。若用观察点集
支撑矩或将同一个GS模型做刚性变换产生输入，需明确它们各自的验证范围；
后者不能自动证明跨独立重建的泛化，也要防止同一基元属性成为身份标记。
已有Teatime/Waldo的R41色彩读出结果保留，但不能替代Transformer任务验证。

先完成并解释R61，再固定下一项实际任务。当前没有据这些文献下载训练
数据、读取ModelNet官方测试集/保留场景，或引入自然梯度、蒸馏、视觉语言
模型等额外模块。
