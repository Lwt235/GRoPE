三维高斯相对同输入三维点 RoPE 提升 2.7573pp，但落后 MLP 0.3356pp，
尚无高斯特有优势，候选不晋级。当前状态见 [研究记录](research_current.md)。

继续在同一二维坐标上调整高斯数量、尺度或训练步数没有新的证据支撑。
下一问题是原生三维空间中，这种参数化是否有普通点 RoPE/非高斯映射不能
替代的效用。这是尚未覆盖的任务条件，不将二维失败说成任务不公平，也不
用一个三维正结果抹去二维适用性限制。完整跨任务和未使用确认仍需完成。

## 可复用的证据与一个必须控制的混淆

代码审查确认：`experiments/round5_cache.py` 为每个 RGB token 保存了预测深度、
内参/位姿、features、mean3 和 cov3。mean3 是 8×8 patch 内 64 个三维点的均值，
并不是 token 中心像素的反投影。`experiments/round5_pairs.py` 中本视图坐标是
精确 token 中心，跨视图坐标则来自 mean3 的投影。这一差异由代码定义确认，
尚未测量它对匹配误差的贡献，不能据此声称发现 R43–R45 失败的主要原因。

因此，不能仅把二维字段换成 mean3 后，把所有变化归因于“三维 PE”。建议：

- 对中心对应任务，以已缓存的 RGB 预测深度在同一中心像素反投影三维位置。
  例如中心在半像素坐标时采用四邻域双线性深度；钳制顺序、单位和相机约定
  必须固定。传感器深度仍只用于既有标签。
- 在相同中心几何下同时准备普通二维点 RoPE 和普通三维点 RoPE 控制。
  保留原 R45 二维点结果为历史参考，但不把它当作几何身份已相同的新控制。
- 在三维点控制之上仅替换位置算子，测试高斯/固定高斯/各向同性与普通
  Fourier、MLP、仿射、自由频率。新增收益必须相对同输入的强控制成立。

这些中心是 token 的位置锚点；待学习高斯场的中心/旋转/尺度是 PE 参数。
两者不等同于从真实 3DGS 优化得到的物理基元，不能混用三种解释。

## 模型与数据选择

优先复用已使用的 R5 场景、图像特征、对应标签及完整双向 Transformer，
使这个实验首先隔离原生坐标与参数化的关系。它仍属于匹配任务，不能冒充
第二个独立下游任务。只有后续其他任务和架构验证才能支持更广的一般性。

三维坐标必须在每次注意力交互的共同参考系中。共同锚点/尺度归一化只能
依据模型可用的输入几何；在所有相应控制中相同。不能用目标深度、可见性
标签、old_eval 分数确定归一化、频段或高斯覆盖范围。比较重点是同一三维
位置输入下的点算子与参数化算子，不能只展示二维到三维的整体变化。

候选仍可保持一个算子：三维高斯场输出三维坐标修正，再产生单位旋转。
需要维度通用的均值/正定精度实现，零修正恢复三维点基线；不是在三维外再
叠加形状相似度、渲染损失或额外值分支。是否采用这一候选、具体坐标规范、
高斯数量/频段/容量、预算与评价标准，均需在实施前完成前瞻说明。

若三维高斯与匹配的普通三维位置算子仍无差别，应停止将“增加空间高斯自由度”
作为收益来源的假设，重新审视任务需要何种位置关系。若出现收益，应先解释
高斯中心、方向/尺度、普通非线性映射和输入几何各自的作用，再做鲁棒性、
实际成本、跨任务与未使用数据确认。没有启动新的静态积分前置门禁。
