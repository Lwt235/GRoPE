# 第五轮独立协议审查：跨场景 RGB 估计几何与两层匹配网络

2026-10-30。本文规定建议协议与可测门槛，不报告实验结果。**本审查尚未确认任何新 RGB-D 数据集或预训练几何权重已经可用**；实际场景、传感器对齐、许可、RGB/深度/位姿完整性及权重来源，以数据盘点为准。不能先把缓存中的不同视频序列当成不同物理场景。

## 首先解决的三个问题

1. **尺度与位姿来源必须说清楚。** RGB 预测深度可能只有相对尺度。禁止用验证/测试真值深度、真值对应或测试 GT 点云给预测几何做尺度/位姿对齐，再声称 RGB-only。若使用数据集标定内外参，主条件应叫“RGB 估计深度 + 已知标定相机”，并给所有同信息对照相同相机信息；严格 RGB-only 条件则连相对位姿都应来自同一冻结 RGB 推断器。不能混用相对深度的尺度和未经对齐的公制平移。
2. **模型不能读取真值可见性 mask。** GT depth 只用于监督对应、评估有效性与独立诊断；不能用于拟合输入 covariance、选择候选 key、剔除预测几何差的 query，或计算输入置信度。方法无关的 RGB 图像边界、padding/crop mask 可以输入所有模型。
3. **避免粗网格决定 PCK 上限。** 本轮建议明确叫 coarse-dense matching。若候选 stride 为 8 px，主指标用 PCK@8px；更严 PCK 和连续像素 EPE另报。先算与网络无关的 nearest-grid oracle 上限。沿用 12/24px 粗 patch 却主报 PCK@3px，主要会测到量化误差。采用 soft-argmax 时也要说明它是概率重心，可能落在多个模式之间。

## 1. 要检验的主张

在相同冻结 RGB 特征和相同 RGB 估计几何下，Gaussian 支撑 PE 能否在两个实际 cross-attention 层中，相对强位置/固定支撑对照，提高**训练后未用过的物理场景**上的对应准确率。几何完全来自输入 RGB 推断与其已知标定；真值深度不成为前向输入。

它检验 Gaussian 参数化 PE 的跨场景实用性，不自动证明“真实优化 3DGS 的每个 primitive R/S 都有独立收益”。从预测深度邻域拟合出的 Gaussian 支撑，应按该来源命名，不能改称训练后的 3DGS primitive。

## 2. 数据盘点与冻结分割

- 先核对每个候选数据集的物理场景 ID、RGB/depth 时间同步、深度单位、invalid 编码、深度到 RGB 的注册关系、相机坐标轴方向和 pose 约定；保存数据来源及校验和。不同拍摄轮次、相邻序列或同一房间的重扫不得跨 split。
- 场景级分开 train/validation/test；任何训练采样、特征压缩拟合、归一化常量和超参数选择都不能读取 test。建议确认评估至少 5 个独立物理测试场景；少于 3 个时，只能交付场景内/少场景可行性结论，不能把大量 frame pairs 充作跨场景重复。
- 预先固定每场景 pair 数上限和时间/帧间隔规则。可以按预先定义的真实重叠分层报告，但不能看到模型性能后删除难 pair。测试 pair 的选择不得使用候选方法的匹配分数或预测几何质量。
- 同一测试视频的相邻帧高度相关。保存 scene、sequence、q_frame、k_frame 身份；评价和 bootstrap 使用这些身份，而不是把 token 当成独立样本。
- 冻结视觉/几何模型的预训练场景可能未知。报告“未参与本轮匹配器训练的场景”，不要在无法核查预训练来源时声称“从未见过的照片/场景”。

## 3. 几何输入合同与泄漏隔离

建议分成互不调用的两个接口：

```
observations(rgb_q, rgb_k, allowed_camera_metadata, frozen_weights)
    -> features, predicted_means, predicted_supports, inference_available_masks

supervision(gt_depth_q, gt_depth_k, gt_cameras, region_grid)
    -> target_coordinates, sparse_target_weights, evaluation_validity
```

前者不得接收后者输出。GT depth 的 valid mask 也属于后者，不能混进候选 key mask。允许模型对可见 query 计算训练损失，但 forward 仍应处理完整 RGB 网格；这与把真实可见性提供给模型是不同的。

| 风险 | 必须检查的行为 |
|---|---|
| GT 深度经局部 PCA、法向、z-buffer 进入 PE | 几何拟合只能读取预测深度/点图；GT 缓冲替换或置零后前向输入逐元素不变 |
| GT target-depth-valid mask 缩小候选空间 | 候选保留所有图像内 RGB token；只有推断可得的公共 mask 可用 |
| 预测几何无效时偷偷过滤评价行 | 用预先固定的有限 fallback/固定支撑，并把失败计入结果；不能按预测器质量挑好行 |
| 使用 ≥95% 正确目标质量筛行 | 本轮不沿用这种依赖 GT 对应保留质量的筛选；只用标准 GT 可见性/测量有效性定义共同评估群体 |
| 相对深度用 GT scale 或 GT rigid fit 对齐 | 主条件禁止；若额外运行有监督校准条件，必须另列，不能混称冻结 RGB-only 几何 |
| 已知 pose 只给新 PE | 所有同信息对照共享 pose/K/预测均值；另标其信息条件 |
| Joint RGB 几何器隐含跨视角匹配能力 | 所有方法使用同一份冻结预测；加入同信息绝对几何 MLP 或投影中心强对照，区分更多几何信息与 PE 结构 |
| 测试 GT 几何误差反过来选滤波强度/模型 | 只作冻结后的诊断，不用于再挑参数或重写主检验 |

预测几何只在 RGB 输入上运行一次并缓存，记录输入图像哈希、冻结模型/权重哈希、预处理、分辨率及相机约定。不得按方法分别重算或微调。若 RGB 几何推断器需要联合多图输入，需固定输入上下文，不能额外包含测试目标深度、测试对应标签或方法特有帧。

从预测 patch 点云计算均值、协方差时保留其几何单位；投影后均值除 token stride，covariance 除 stride²。协方差是区域支撑，不等同于中心误差方差。SPD floor、越界处理和 fallback 规则在 validation 阶段冻结。

## 4. 标签、可见性与评价群体

对查询网格点，用注册到 RGB 的 GT depth 反投影、GT 相机变换和目标 GT depth 一致性检查生成连续目标坐标。非正深度、GT 缺测、画幅外与真实遮挡进入明确的无监督/无匹配类别约定；同一规则用于全部方法。**不要求目标 token 中心在同一表面**，避免再次删掉边界困难点。

深度一致性容差应按传感器单位预先固定，例如绝对容差与相对深度容差的组合；这只是建议形式，具体数值需数据注册验证后在训练/验证阶段冻结。缩放 RGB、depth 与 K 时统一半像素坐标约定，不用跨深度边缘的双线性插值伪造三维表面。

可以使用最近候选类别监督，或连续投影到四个邻接候选的双线性软标签；先固定一种主目标。后者只编码空间插值，不证明真实区域 overlap。若只训练/评价可见有对应点，结果必须叫“条件于 GT 可见对应的匹配”，不得宣称解决遮挡拒绝或开放集匹配。

同时报告：GT 有效 query 占全部 query 的比例、每场景有效 pair/query 数、各类无效原因、预测几何 fallback 比例。GT 有效性可用于评价筛选，不可作为 attention key mask 或查询输入特征。

## 5. 相同 backbone 与两层网络

所有变体共用同一个冻结视觉 backbone、层输出、特征插值方式和归一化；禁止分别选最有利层。若做 PCA/特征压缩，仅在训练图像拟合一次，所有方法共享；禁止按场景或测试集重新拟合。特征缓存按 frame 保存，不按对应标签聚合。

主网络固定为两层 cross-attention，包含相同的 Q/K/V、残差、归一化与 FFN；PE 只替换每层 Q/K 的位置变换，V/输出路径与内容容量相同。是否双向更新、参数是否共享、最终匹配 head、Head 数、频率集合及温度规则都在试验前冻结。可用宽度 96、2 Heads×48 维沿用当前已审计 PE，但这是实现建议，不应在看到测试后改结构。

所有主位置方法使用一致的 Q/K 范数约定；若比较普通 Expected RoPE 的未归一化版本，须明确它是另一个机制消融。固定支撑的 q/k 两端都固定，trace/area 两端都替换，不能把单边替换误称完整形状消融。

建议最小主对照集合：

1. 投影均值位置 RoPE，获得相同预测均值/相机信息；
2. 双侧固定支撑、后归一化 PE；
3. 完整支撑、后归一化 Gaussian PE；
4. 双侧 trace 匹配各向同性；
5. 双侧 area 匹配各向同性；
6. 同信息绝对几何 MLP，或经同验证预算选择的强投影中心对照。

缓降滤波可作为预先登记的次候选；不要用多次探索后的最佳家族与未调优位置基线比较。所有方法报告实际有效训练参数，归一化/Head/FFN 容量一致；多出的几何 MLP 参数如实记录。模糊 floor、Gaussian 强度、滤波家族的调参网格与预算先登记。

## 6. 开发、确认与可测门槛

先用训练/验证场景做单种子可行性开发，确认坐标、梯度、过拟合小批次、网格上限和算力。不得看确认测试结果选 architecture、频率、几何器、PCK 阈值或训练步数。随后冻结协议和输入哈希，执行 5 个预先指定的新训练种子；初始化、批次顺序、增强和选 checkpoint 规则配对一致。每种子按 **scene-macro validation CE** 选择检查点，包括初始状态；测试只用于最后确认。

推荐主门槛为点对应任务的路线 A；如改用路线 B，须在确认测试前明确选择，不能测试后在二者之间择优：

| 门槛 | 路线 A：主 PCK | 路线 B：主概率分配 |
|---|---|---|
| 实际改善幅度 | scene-macro PCK 至少 +1.0 个百分点 | scene-macro CE 相对降低至少 2.0% |
| 不确定性 | 候选减预定强基线的配对 seed/scene CI 下界 >0 | CE 差的配对 seed/scene CI 上界 <0 |
| 稳定方向 | 至少 4/5 训练种子同向；逐场景值全部报告 | 同左 |
| 防止单指标换取代价 | CE 相对恶化不得超过预定 2% 容忍值 | PCK 的非劣效 margin 预设为 −0.5pp，并要求其区间下界高于该 margin |

“预定强基线”应在开发 validation 阶段从位置 RoPE/双侧固定/同信息控制中选定并冻结；仍报告所有对照。形状贡献另要求 full 对双侧 fixed、trace、area 的方向与 CI 支持；若仅对弱基线过门槛，不得宣称协方差各向异性贡献成立。若路线 A 的 CE 容忍值只看点估计，则报告为经验 guardrail，不能称统计非劣效。

选择 seed/scene 双层或交叉 bootstrap，固定测试场景权重并预先定义 scene-macro 主汇总；每次同时重采样训练种子与测试物理场景，并在场景内按 query 相机/连续帧块聚类，保持各方法共享同一重采样。5 个训练种子不是 5 个独立测试数据集。只有很少场景时，CI 本身不稳定，需报告留一场景敏感性与每场景结果，限制总体外推。多个探索性对照不称同时覆盖校正后的结论。

如果主门槛未通过，保留负结果，明确是否因几何预测、尺度/pose 不兼容、网格上限或 PE 本身。不得重新选测试子集、噪声条件或最佳训练种子来通过。

## 7. 计算与存储约束

- 先缓存冻结视觉与几何特征，只训练两层网络。一个起步配置是 192×144、stride8、每视角 432 tokens、batch≤8；先测单步时间和峰值显存，再固定训练步数/预算。避免在确认阶段为某个方法单独延长训练。
- 软标签保存每 query 最多四个 key 索引和权重；不为所有 pair 永久保存 432² 的稠密 GT 分布。按 frame 缓存特征，按 pair 缓存稀疏监督。预测概率可只为最终确认/审计的固定子集保存，其余保留可重放 checkpoint 与逐场景统计。
- 初步训练建议先≤300步开发，确认在 validation 曲线允许的统一 1,000–2,000步范围冻结。上限是计划建议，需实际吞吐测量后确定；不能声称已经跑完或确保足够收敛。
- 单线程 CPU 准备数据，使用当前安全 launcher 重新检查空闲 GPU；7→0选择、不抢占其他进程。冻结大模型推断与匹配训练分阶段，默认仅占 1 张空闲卡；额外并行仅在再次确认空闲后进行。
- 先设单模型训练显存目标≤8GB、含冻结模型预处理≤16GB；超出先减 batch/缓存，不通过降低某一方法分辨率获得不公平比较。开发预算建议先≤30 GPU分钟，完整确认总预算先登记为≤4 GPU小时；如果测得无法完成该预算，先缩小所有方法的统一配置，再冻结确认。
- 保存环境/设备、代码和数据哈希、训练时间/显存、所有验证历史、选定 step、逐 scene/query-camera 指标及概率/模型复现入口。确认数据和完成实验目录禁止覆盖。

## 8. 进入确认实验前的最低验收

1. 数据盘点确认是真实 RGB-D，场景分割和相机/深度注册正确；至少一个已知相机运动与同帧投影闭环通过。
2. GT depth/pose 标签缓冲扰动隔离测试通过；允许的 camera metadata 与禁止的 GT 监督字段在代码接口中分开。
3. 同一数据、mask、backbone/预测器输出由所有方法共享；source/target 几何支持、像素与 covariance 单位正确。
4. 小批次能过拟合，所有方法梯度有限；stride 的 oracle 上限、无效原因与 fallback 比例已测。
5. 测试物理场景清单、pair 选择规则、主指标/阈值、门槛路线、对照、5 种子、训练/调参预算和统计代码已经冻结；测试数据未用于模型选择。

任一项缺失时应先交付可行性结果，不能把 5 种子和大样本 token 数替代基本有效性。
