# 原生数据的逐对象缓存验证

**已验证一种省磁盘的数据准备方式：每次暂存一个原始对象，校验完整 SHA-256，调用原转换器，持久保存紧凑缓存后删除这份临时副本。** 原始 TRAIN 文件保持只读。该流程不改变高斯参数化、位置编码、训练或评价规则，也没有打开官方 TEST 基元。

本次从既有 fit 划分中，按发布文件大小，在 MACGS 和 ModelNet 两类来源各选最小、中位、最大文件，共六个旧对象，选择先于本次顶点读取固定。文件大小约 1.8–190.1 MiB，总计 247.14 MiB。两类最小文件又通过用户指定 hf-mirror.com 直连读取一次，共约 4.01 MiB；它们是同六个对象中的重复验证，不能计为八个独立样本。

| 检查 | 实际结果 |
| --- | --- |
| 本地六对象：中心、完整协方差、外观、索引、标签 | 所有数组元素与旧 fit 缓存完全一致 |
| 原转换统计：原点、RMS、特征值、floor 分位数等 | 六对象均完全一致 |
| 镜像下载的两个旧对象 | 发布文件哈希通过，数组和统计同样完全一致 |
| 在两个真实对象提交后中断，再续接 | 已完成行通过身份和内容检查，只接续其余对象 |
| 短响应、错误哈希、已提交行损坏 | 三项自动测试通过；错误数据不会被标为完整缓存 |
| 成功后的原始暂存文件 | 0 个；只保留缓存和过程元数据 |
| 实际本地转换 | 81.24 s；进程峰值 RSS 约 388.1 MiB |
| 两个镜像文件完整流程 | 5.94 s；两次文件请求，无失败、无代理 |

最大文件的原转换曾触发 60 秒栈观察，随后自行完成。它不是退出或失败，没有因为观察超时重启；六对象比较均通过。这个小型运行只用于验证数据一致性与中断边界，不用于外推全量处理吞吐。

实现沿用原 `read_vertices/native_arrays`，因此随机抽取身份、2,048 基元、中心归一化、float64 协方差、原几何 floor、外观和索引类型均未改变。缓存按既定完整列表预分配，完成行持久化后才写提交记录；续接时核对缓存身份和已提交行哈希。下载逐文件验证字节数与 SHA-256，暂存始终限于单对象；异常保留该对象的有界临时文件，有限重试不累积多份副本。仅清理本流程自己创建的临时副本，不删除原始 TRAIN。

按前一阶段的完整 TEST 元数据与原转换器 schema，6,090 对象的缓存数组约 **1.208 GiB**，最大的原始 TEST 文件约 **149.5 MiB**。这使保留 75.83 GiB 原始文件不再是算法上的必要条件；但尚未运行全量 TEST 流程，也未验证每个测试文件的 PLY 内容。正式采集时仍需确认空间、并预先固定模型、强对照与分析。本次在工作区有足够空间的磁盘上保留原 50 GiB 余量完成验证；用户指定数据盘约 31 GiB 空闲的问题并未通过降低余量或转移正式数据而隐藏。

**决定：保留已验证的逐对象缓存实现，作为后续完整测试采集的选项。** 科学主线仍等待原生固定球形三个完整拟合及统一评价，再确定强对照和种子复现范围。本记录只解除了一部分数据准备成本问题，不增加新的任务效果证据。
