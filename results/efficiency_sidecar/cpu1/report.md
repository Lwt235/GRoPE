# 训推效率独立探索：首批 CPU 结果

本会话建立了私有实例适配器并完成首批验证，**没有改变主实验，未使用 GPU**。
主训练的冻结 Python 源文件哈希仍全部一致。本次只使用单线程、nice=15 的低优先级 CPU，
耗时 341.7 秒。GPU 全部有任务，因此没有启动或后台安排 GPU 基准。

## 做了什么

1. 保留已有 query 投影重排作为已知基线，不能把旧成果重新计为新发现。
2. 新原型将 `(ci-cj)^T Pi (ci-cj)` 展开为 10 维多项式特征的矩阵乘法；
   几何仍为 FP64，网络仍为 FP32，欧氏距离保留直接位移计算。整体仍是 O(N²)。
   该式属于标准代数展开，不宣称新的几何理论。
3. 固定球形对照直接产生与旧 hook 相同的径向特征，避免先计算再丢弃高斯形状关系。
   它修正效率对比中的实现冗余，不是完整五维的专属收益。
4. 对 Linear→GELU 使用非重入激活重算，反向时重算预激活以节省保存空间。
   这是一项常规内存优化；是否加速必须实测，所有对照同样应用。

## 正确性证据与限制

- 合成输入包含 FP64/FP32 三模型及三适配组合，共 18 个配对全参数梯度检查；
  最大梯度相对 L2 差 4.13e-07。
- 旧 validation 前 16 对象，64/128/256/512/1024 基元描述子比较最大绝对差 9.31e-10；
  固定球形直接构造在所有这些输入上与原版一致。
- 三个旧 seed11 checkpoint，各前两个 validation 对象、512 基元，最大 logit 差 2.86e-06，
  未改变这六个模型—对象分类结果；这不是全验证集任务确认。
- 私有内存模型的一步 AdamW 参数差最大 3.62e-05。运算重排并不保证长期训练逐位一致；
  本次未训练新的科学模型，也不声称长期精度已验证。
- 极端条件数 1e10、近重合中心的压力检查出现微小消去误差，完整数值保留在 JSON。
  对未来更极端/可学习几何不作保证；适配器明确拒绝需要几何梯度的输入。

单线程、同一旧对象批 B=16、每组合 5 个计时块，每块 3 次，交错次序；单位 ms。
主服务器有其他任务，保留原始块耗时；下表中位数只供实现筛选，不能外推 GPU。

## CPU 整模型微基准

B=1、N=512，单位 ms；前后向不含优化器、数据加载/搬运。3 个计时块、每块一次；
是短时诊断，四变体的次序在三块中未完全平衡；CPU 上的优势、退步或波动均不等于 GPU 结论。
后续 GPU 脚本使用四块平衡循环次序。

| 方法 | 模式 | 原版 | 已有投影重排 | 加新几何路径 | 再加激活重算 |
| --- | --- | ---: | ---: | ---: | ---: |
| relative5 | inference | 414.48 | 197.09 | 191.61 | 192.62 |
| relative5 | forward_backward | 1628.64 | 1055.26 | 1059.54 | 1144.62 |
| distance_mlp | inference | 536.09 | 195.07 | 193.79 | 193.81 |
| distance_mlp | forward_backward | 1357.90 | 808.85 | 812.88 | 871.60 |
| fixed_isotropic5 | inference | 523.56 | 211.48 | 194.45 | 195.20 |
| fixed_isotropic5 | forward_backward | 1608.90 | 1059.21 | 1052.32 | 1100.13 |

本轮决定：主要的整体加速仍来自**此前已有**的投影重排。本次新增几何路径在五维
512-token CPU 推理上仅有小幅改善，在前后向上没有观察到进一步加速。
激活重算在这里增加了前后向时间，因此保留为省内存候选，不称为训练加速。
Distance 的两种非重算 factored 路径实际相同，其耗时差也提示短时测量存在波动。
CPU 几何局部改善不能替代 GPU 整体性能结论。

## 内存证据

在 B=1、N=128 的五维模型中，用 autograd hook 统计前向保存供反向使用的独立存储：
原版 40.734 MiB，已有重排 16.921 MiB，
再加激活重算 10.921 MiB。
后两者相差恰好一份 B×N×N×96 的 FP32 预激活。
在 B=16、N=512 下，这份张量理论大小为 1.5 GiB；**不是实测 GPU 峰值减少 1.5 GiB**。
隐藏关系仍然保存，没有消除二次复杂度。

## 下一步与边界

GPU 脚本 `experiments/efficiency_sidecar/benchmark_gpu.py` 已准备，但尚未执行 GPU 路径。
它要求主训练队列及自动评价结束，并要求整卡空闲；不会主动抢占或修改主队列。
测量方案包括三模型、公平优化、1/4/16 batch、128–1024 基元，以及推理、前后向、
含裁剪和 AdamW 的步骤。后者只更新私有内存副本，不写任何科学 checkpoint。
数据 IO 与传输未包含，未来端到端训练吞吐需要另外测量。

当前只保留实现候选，不把 CPU 微基准当作论文 GPU 结果，不将其接入正在训练的主方法。
若 GPU 只省内存或反而变慢，也将如实报告。未来可研究逐基元精度/log 协方差缓存与旋转复用，
但本次没有实现，也没有改变现有数据管线。
