Abstract

Can a neural network learn to render 3D Gaussian splats on its own, with no rasterizer in the renderer? We present GaussianRenderFormer, a transformer that takes a set of Gaussians and a camera and outputs the image directly. Each Gaussian becomes one token in a view-independent encoder, and a view-dependent decoder turns small patches of camera rays into pixels by attending to those tokens. Trained on 26,820 Objaverse objects pruned to 20,000 Gaussians each, GaussianRenderFormer renders 300 unseen objects at 38.08 dB PSNR against the full, unpruned splats, while rasterizing the same pruned input reaches 44.02 dB. The gap is not one of generalization, and our diagnostics are consistent with a bottleneck in the view decoder: telling it the projected footprint of each Gaussian, which it could in principle infer, adds 1.4 dB. Under-training is not ruled out.

Method

Each Gaussian's 14 parameters are embedded as one token, and a view-independent scene encoder (top) lets these tokens exchange information, using a 3D rotary embedding of their centers. For each view, the image is split into 4×4-pixel patches, and each patch becomes a token built from its camera rays. The view decoder (bottom) lets these tokens attend to the scene tokens, using a 2D rotary embedding of where each Gaussian lands in the image and an embedding of its projected footprint, and a DPT head turns them into pixels.

GaussianRenderFormer keeps RenderFormer's two-stage layout and starts from its pretrained weights. Three changes adapt its view decoder to Gaussians:

  • A 2D rotary embedding of where each Gaussian lands in the image, on the cross-attention.
  • The projected footprint of each Gaussian, its 2D covariance in the image, on the attention keys.
  • Smaller patches of 4×4 pixels.

Where each Gaussian lands and how large it appears are computed per Gaussian, while which Gaussians cover each pixel and how they blend is learned.

Limitations

  • GaussianRenderFormer is not yet a practical replacement for a rasterizer: it stays several dB below rasterizing the same input, is several hundred times slower and needs far more memory.
  • We train and evaluate on single objects viewed from outside. Rendering a full scene, with the camera inside it, remains open.
  • It renders well only in its training configuration. Other input sizes, camera distances, resolutions and fields of view cost it quality.
  • It uses only the view-independent color of each Gaussian and cannot relight.
