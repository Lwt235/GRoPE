# 原生紧凑缓存到预测与分组指标的执行检查

**旧缓存的执行检查已通过，正式 TEST 验证尚未启动。** 新增入口读取既有逐对象紧凑缓存，调用未改动的原生 Transformer 和六种评价条件，保存带对象身份的预测，并按固定来源/历史对象复用分组输出指标。它不下载数据、不训练、不选择最终模型。

| 检查 | 结果 |
| --- | --- |
| 缓存数组与对象顺序 | 既有六个旧 fit 对象，全部五组数组及 ID 与原缓存一致 |
| 同模型、同输入的六条件推理 | relative5 / Distance 的既有种子11，共12组；logits 和类别均完全一致 |
| 旧完整验证集回放 | 两模型各765对象，logits 和类别均完全一致 |
| 独立指标计算 | 最大差 1.94e-16 |
| 历史分组的元数据对应 | 完整6090；历史复用2245；无已知历史对象重叠3845，后者覆盖60类 |
| 完成文件复用 | 按模型、缓存、条件、分组、代码身份验证后复用；不会静默覆盖 |
| CPU 检查 | 不均衡类的 mCA/OA 区别、空组、不完整历史清单、错序清单对齐均检查 |

检查在空闲 GPU5 完成，约 10.57 秒；此耗时只属于小型执行检查，不是完整测试吞吐。六个旧对象的模型/条件重复不增加独立对象数量，也没有产生新的用途证据。

初次运行前检查发现，旧 TRAIN 目录没有后来 TEST 元数据新增的 source 字段。仅为旧检查的分组视图补上原有类别范围映射，缓存本身与科学比较未改变；修正前锁和脚本保留。

官方测试对象内容与得分仍未读取。下一步仍需先完成当前原生归因，确定固定复现和正式确认的最终模型/强对照，再固定确认分析与模型身份后开放测试。全量官方成绩和历史对象分组必须一并报告，不能按分数选择更有利的人群。
