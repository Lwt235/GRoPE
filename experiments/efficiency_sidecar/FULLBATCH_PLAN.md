# 融合反向：正式批次验证

目标：判定已验证的单项梯度融合在实际 B16/N512 下的速度/显存取舍。
当前主训练 CONFIG 与锁均为 batch_size16/tokens512；只复用旧seed11模型和旧validation前16对象。
不修改主训练，不读取当前开发分数，不以速度结果更新PE科学结论。

假设：B4 的带宽节省在 B16 仍可改善完整步骤；竞争解释为额外梯度存活、分配或调度抵消收益。
固定比较：已有 geometry_factored 与相同实现加 fused_hidden_gradient；relative5/Distance 同等适配。
保持公式、参数、FP32网络/FP64几何、TF32关闭、样本流和损失不变。不增加其他优化。

执行：
1. 检查实时资源。独占卡为空且低利用率时可做 exclusive；没有空卡时只做显式 shared。
   shared 只允许与记录在主项目队列中的任务共享，不停止/修改其他进程。
2. 实际B16/N512下比较输出、所有参数梯度、一步AdamW更新并测峰值显存。
   沿用上一轮数值容差。若失败或超过12GiB上限，保留失败结果，不减batch冒充正式批次。
3. 8块，每块A/A、B/B四标签平衡轮换；每标签从同一权重和优化器初始化，预热2步、计时4步。
   CPU热池取样、H2D、旋转/jitter、完整前后向、梯度裁剪和AdamW计入整步。
   固定schedule在计时前生成；不含冷盘读取、正式选模、checkpoint或当前双来源调度。
   报告wall-time、CUDA span、配对改善、同实现漂移、allocated/reserved峰值。
4. 若仅共享结果：可判定正式batch的显存可行性及探索性速度信号，不称独占复现已完成。
   全部结果保留；若收益弱/变差，不增加模块补救。主实现仍不自动启用。

单GPU、nice15、CPU1线程、12GiB allocator上限，初始至少24GiB空余、运行保留至少8GiB。
B16候选从B4估计需要约9.5GiB，因此不能沿用先前小批次6GiB上限；这是资源适配，不改模型。
每阶段最多10分钟，组间释放缓存。出现陌生GPU进程只停止本测试。
无后台轮询/等待器；独占模式留为可重用命令，不在无资源时循环占卡尝试。
