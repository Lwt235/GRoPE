# 用户授权的共享 GPU 初测

用户在首轮 CPU 探索后明确允许与已有任务共享显卡。这一授权更新此前“必须等待主训练结束”的资源约束；
旧 CPU 结果和当时的资源决定保持不变。主训练代码、数据、模型和队列仍不修改。

本次只使用记录在主队列中的同项目进程所在 GPU，拒绝与未识别进程共享。
选卡时至少留有 24 GiB，测试 PyTorch 分配上限 6 GiB，运行中至少保留 8 GiB；
发现新增进程或 PID 身份变化时停止自身。nice=15、单 CPU 线程，每组测量后休息 0.15 秒。
共享计算会造成一定竞争，这些措施不保证主任务零减速；不改变他人的进程或调度。

固定小规模：三种方法×四种实现，B4/N512 与 B1/N1024，推理、前后向、含 AdamW 的步骤。
每组两次预热、三次计时调用，四块循环平衡实现次序；最多十分钟。
保留每组显卡占用快照及全部块耗时。共享计时只作工程初筛，不作为独占 GPU 的正式速度结论。
GPU 上核对输出和全部参数梯度；优化器仅更新私有模型副本，不保存科学模型。

运行入口：`benchmark_gpu --share-project-gpu --output results/efficiency_sidecar/shared_gpu1`。
该授权不会将共享模式自动接入主任务，也没有启动持续抢占资源的后台任务。
